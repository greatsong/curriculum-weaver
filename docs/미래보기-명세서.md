## 한눈에 보기

| 항목 | 결정 |

| 색 | 3D 교육과정 성운 토큰(네이비 배경, 교과색 그대로, 과학 #4ADE80 유지). 강조는 하늘·파랑(연결 #7DD3FC, 주 버튼 #60A5FA). 초록 강조·타임스톤·스톤 6색 없음 |
| 움직임 | 그래프 첫 표시 페이드 440ms, 강조 전환 150ms, 카드 준비 200ms만 |

## 최신 사용자 결정 (2026-10-03, 아래 본문보다 우선)

1. **과목과 키워드를 컴퓨터과학 그래프처럼 선으로 잇는다.** 행성(과목)에서 자기 위성(키워드) 하나하나로 얇은 선을 긋는다(교과색, 불투명도 0.35, 굵기 1px, 행성 경계에서 위성 원 경계까지). 본문의 "바큇살 선 금지"(1부 G4, 2부 §0·§3-1·§9·§10-3)는 이 결정으로 바뀐다. 위성 배치(행성 가까이 불규칙, 같은 거리·각도 금지)는 그대로라 사방으로 뻗는 마인드맵 모양은 되지 않는다.
2. **연결선(키워드 ↔ 키워드)은 두 끝 교과색의 선형 그라데이션**이고, 선들이 겹치는 곳은 빛이 더해지는 가산 혼합으로 그린다(`mix-blend-mode: plus-lighter`, 지원하지 않으면 `screen`). 연결 이름표 글자는 하늘색(`#7DD3FC`) 그대로.
3. **연결의 강하고 약함은 선의 밝기로 나타낸다.** 연결 찾기 응답의 연결마다 `strength`(정수 1~3)를 받는다.
   - 3(강함): 두 키워드가 같은 대상·개념을 직접 다루어, 한 활동 안에서 두 성취기준의 핵심 내용이 함께 다뤄진다.
   - 2(보통): 한 활동에서 함께 다룰 수 있으나 한쪽이 보조 역할이다.
   - 1(약함): 연결은 성립하지만 활동을 따로 설계해야 이어진다.
   - 표시: 3 = 불투명도 0.95·굵기 2.2px, 2 = 0.65·1.8px, 1 = 0.38·1.5px. 범례에 "선이 밝을수록 강한 연결"을 더한다. 근거 목록 한 줄에도 강도를 글자로 붙인다(`강함`·`보통`·`약함`).
   - 프롬프트(1부 §5-1) 연결 원칙에 15번을 더한다: "15. 연결마다 strength를 1~3 정수로 적으세요. 3은 두 키워드가 같은 대상·개념을 직접 다루어 한 활동에서 두 성취기준의 핵심 내용이 함께 다뤄질 때, 2는 한 활동에서 함께 다룰 수 있지만 한쪽이 보조 역할일 때, 1은 연결은 성립하지만 활동을 따로 설계해야 이어질 때입니다. 약한 연결을 강하게 적지 마세요." 응답 형식의 연결 항목에 `"strength": 2`를 더한다.
   - 서버 검증(1부 §2-5)에 V11-1을 더한다: `strength`가 1·2·3이 아니면 2. 화면 데이터 `concepts[]`에 `strength` 포함.
4. **사용자 손그림(2026-10-03)으로 노드 모양 확정: 과목 노드 = 큰 원, 원 안에 과목 이름과 그 과목의 성취기준 코드.** 같은 과목의 성취기준은 원 하나로 묶는다(예: "과목 1 · 성취기준 1, 2"). 원 크기는 모든 과목이 같다. 키워드는 원 둘레에 짧은 선으로 달리고, 연결선은 키워드끼리 먼 과목 사이를 건넌다. 과목 원들은 360° 바깥 링에 손그림보다 훨씬 멀리 떨어뜨린다(손그림은 종이에 크게 그리려고 가깝게 그린 것). 같은 과목 안의 두 성취기준 사이 연결은 그래프 선에서 빼고 근거 목록에만 둔다.

## 0. 문서 기초

### 0-1. 용어

| 용어 | 뜻 |
|---|---|
| 성취기준 | 2022 개정 교육과정 성취기준 한 항목. 식별자는 `key`(코드가 여러 과목에 겹치면 `code|과목`), 화면 표시는 `code` |
| 조합 | 교사가 고른 성취기준 2~6개 |
| 키워드 | 성취기준 **원문에 있는 말 그대로** 뽑은 짧은 명사구. 성취기준마다 3~4개 |
| 연결 | 서로 다른 두 성취기준의 키워드 하나씩, 모두 2개를 잇는 것. 종류는 `same`(같은 대상)과 `method`(활동으로 다룸) 두 가지 |
| 연결 이름 | AI가 연결에 붙인 2~10자 명사구. 원문이 아니다 |
| 근거 | 그 연결의 두 키워드를 한 활동에서 어떻게 함께 다루는지 쓴 한 문장 |
| 연결되지 않은 성취기준 | 어느 연결에도 들지 않은 성취기준 |
| 관점 | 수업 아이디어를 만드는 시각 8가지(§3) |
| 수업 아이디어(카드) | 관점 하나로 만든 짧은 카드. 제목 + 활동 문장 + 결과물 문장 |
| 축 | 카드가 바탕으로 삼은 연결(1~2개) |
| 비중이 작은 성취기준 | 그 카드에서 활동이 거의 없거나 빠진 성취기준 |

### 0-2. 하지 않는 것

- 차시·단계·평가 계획, 자료 목록을 만들지 않는다. 카드는 발상 자료이고 수업안이 아니다.
- 연결이 교육과정상 공인된 것처럼 보이게 하지 않는다. 키워드는 원문, 연결 이름과 근거는 AI가 만든 것임을 화면에서 구분한다.
- 이어지지 않는 성취기준을 억지로 잇지 않는다. 연결 0개도 정상 결과다.

### 0-3. 사용자 결정 (모두 지킨다)

1. 기능 이름은 **"미래 보기"** 하나만 사용한다.
2. 연결은 **과목 A · 키워드 · 키워드 · 과목 B**로 읽혀야 한다.
3. 색은 3D "교육과정 성운"의 느낌. 초록 강조 콘셉트(타임스톤)는 없앤다. 단 **과학 교과군 색 #4ADE80은 3D와 같이 유지**하고, 강조색은 초록이 아닌 색을 사용한다.
4. 카드는 짧게, **4~5줄**, "이런 수업도 괜찮겠다"는 느낌. 차시·단계·평가 계획 금지.
5. **키워드 가독성이 최우선.** 3D가 아니어도 된다. 효과는 깔끔하게, 과한 입자·폭발·잔상 금지.
6. 관점은 8개: 지역 문제·학교 생활·데이터 탐구·과학 탐구·창작 프로젝트·역사적 관점·진로·직업·지구적 문제.
7. 키워드는 성취기준 **원문에 있는 말만**. 억지 연결 금지. 이어지지 않는 성취기준은 그대로 둔다.
8. 대상: 교사 연수(약 10명, 일반고 교사), 노트북 화면. 성취기준을 이미 아는 교사(코드 검색·여러 코드 붙여 넣기), 2~6개.
9. 화면 문구에 **"자리"(별자리 포함)를 쓰지 않는다.**
10. 그래프: **과목마다 키워드 여러 개가 그 과목 가까이 한 덩어리로 모이고, 그중 소수만 멀리 떨어진 다른 과목의 키워드와 이어진다.** 마인드맵(과목 중심에서 키워드가 사방으로 뻗는 모양) 금지. 바큇살 선 금지.
11. **연결 그래프는 "미래 보기"를 누르기 전에 먼저 보여 준다.** 교사는 그래프를 보고 조합을 고친 뒤 "미래 보기"를 누른다.
12. 좌우 두 편 배치 금지. 과목 덩어리는 **화면 중심 둘레 360° 전 방향에 불규칙하게 흩어지고**, 연결된 과목끼리는 가능하면 멀리 마주 보며 선이 안쪽 공간을 가로지른다.
13. 한국어 UI 문구 원칙: 대시(—)로 문장 잇기 금지, 은유·의인화·과장 금지, "견주다·뜨다·쓰다(사용 의미)·단추·그냥·~해 보세요(남발)" 금지, 종결 어미 통일, 내용 없는 짧은 선언문 금지.
14. 한 과목이 중심처럼 보이지 않게 한다(재난 조합 시안을 보고 "너무 한 과목이 주인공 같다"). 연결은 서로 다른 과목 쌍에서 고루 찾되 억지 연결 금지가 우선이고, 화면은 모든 과목을 대등하게 보인다.

## 1. 기능 목적·대상·흐름·성공 기준

### 1-1. 목적

교사가 고른 성취기준 2~6개가 **원문의 어느 말에서 이어지는지** 보여 주고, 그 연결을 바탕으로 **관점 8가지의 수업 아이디어**를 짧은 카드로 보여 준다. 교사는 조합이 융합 수업이 되는지 판단하고, 아이디어 하나를 골라 프로젝트 설계를 시작한다.

### 1-2. 교사가 얻는 것과 다음 행동

| 얻는 것 | 화면 요소 | 다음 행동 |
|---|---|---|
| ① 성취기준들이 원문의 어느 말에서 이어지는지 | 연결 그래프 + 연결 근거 목록 | 연결이 약하면 조합을 고친다 |
| ② 이어지지 않는 성취기준이 무엇인지 | 그래프의 "연결된 키워드 없음" 표시 | 빼거나 바꾸거나, 그대로 두고 활동으로만 다룬다 |
| ③ 같은 조합으로 가능한 수업 아이디어 8가지 | 관점별 카드 | 하나를 골라 **프로젝트 시작**(제목·설명이 채워진 채 프로젝트 만들기로 이동) |

①②는 판단 근거, ③은 발상 자료다. 그래서 ①②가 ③보다 먼저 나온다(사용자 결정 11). 연결되지 않은 성취기준에 "빼기"를 권하는 별도 버튼은 두지 않는다. 교육과정 운영상 반드시 넣어야 하는 성취기준일 수 있으므로 사실만 알린다.

### 1-3. 흐름

```
① 성취기준 고르기 (2~6개, 코드 검색·여러 코드 붙여 넣기·예시 조합)
      │  고른 성취기준이 2개 이상이 되고 0.7초 동안 바뀌지 않으면 연결 찾기 시작 (약 6초)
      ▼
② 연결 그래프 + 범례 + 연결 근거 목록 (자동 표시)
      │  교사가 확인하고, 필요하면 ①에서 조합을 고친다 → ②를 다시 계산
      ▼
   결정 줄: [성취기준 담기]   [빠른 | 정밀]  [미래 보기]
      │  "미래 보기"
      ▼
③ 관점별 수업 아이디어 8장 (준비되는 대로 채워짐, 빠른 모드 약 10초)
      │
      ▼
   카드의 [프로젝트 시작] → 프로젝트 만들기 화면 (제목·설명 미리 채움, 고른 성취기준 담김)
```

- "미래 보기"는 연결 계산이 끝나기 전에도 누를 수 있다. 카드 생성은 같은 조합의 연결 계산 결과를 기다려 함께 사용한다.
- 카드를 만든 뒤 조합을 바꾸면 카드는 모두 지운다.
- 상태는 URL에 기록한다: `/futures?codes={key},{key}&model=precise`(빠른 모드면 `model` 생략).

### 1-4. 성공 기준 (교육적)

연수 현장에서 처음 써 보는 교사가:
1. 그래프를 보고 1분 안에 연결 하나를 **원문 키워드 두 개와 근거로** 설명할 수 있다.
2. 연결되지 않은 성취기준이 있으면 그것이 무엇인지 말할 수 있다.
3. 카드 8장을 한 화면에서 훑고 하나를 골라 "프로젝트 시작"을 누를 수 있다.
4. 카드의 어떤 말이 성취기준 원문이고 어떤 말이 AI가 만든 것인지 구분할 수 있다.

내용 수준의 측정 기준은 §8.

## 2. 연결 찾기 내용 규칙

### 2-1. 입력

- 고른 성취기준마다 `code`, `subject`, `content`(원문).
- 참고 자료: 이 조합 안에서 이미 검토된 교과 연결(앱의 연결 데이터 중 게시 상태, 최대 15개). 항목마다 주제·근거.
- 검토할 성취기준 쌍: 서버가 고른 성취기준의 가능한 쌍 전체를 만들어 넣는다(2개면 1쌍, 6개면 15쌍). L8 적용에 사용한다.

### 2-2. 키워드 규칙

| 번호 | 규칙 | 이유 |
|---|---|---|
| K1 | 성취기준마다 **3~4개** | 6개 성취기준이면 많아야 24개. 연결에 든 키워드가 묻히지 않는다 |
| K2 | 구성: 그 성취기준이 다루는 **대상·개념 2~3개 + 학생 활동을 나타내는 명사 0~1개**(토의, 발표, 논증하는 글, 조사 등) | 2022 개정 교육과정 내용 체계의 "지식·이해"와 "과정·기능". 활동어가 있어야 국어·화법·작문처럼 기능 중심 성취기준이 정당하게 이어진다 |
| K3 | **원문 그대로**, 2~12자. 고치거나 바꿔 말하지 않는다. 원문에서 뜻이 서는 가장 짧은 구절('신체적, 정신적 질환 예방'보다 '질환 예방') | 원문 일치가 왜곡을 막는 가장 강한 장치. 짧을수록 그래프에서 잘 읽힌다 |
| K4 | 가운뎃점·쉼표로 묶인 말에서 **꾸미는 말만 떼지 않는다**('준언어적'이 아니라 '준언어적·비언어적 표현') | 조각은 원문에 있어도 뜻이 끊긴다 |
| K5 | 키워드가 아닌 것: 행동만 나타내는 말(설명할 수 있다, 탐구한다, 이해하고, 파악한다), 어느 성취기준에나 있는 말(자료, 사례, 방법, 내용, 과정, 문제, 탐구), 조건·꾸밈만 담은 말(자신의 수준, 활용한 사례) | 원문에 있다는 조건만으로는 걸러지지 않는 실패 유형 |
| K6 | 한 성취기준 안에서 뜻이 겹치면 하나만('식생활문화'와 '건강한 식생활 문화' 가운데 하나) | 같은 말이 두 번 보이면 다른 개념으로 읽힌다 |

### 2-3. 연결 규칙

| 번호 | 규칙 | 이유 |
|---|---|---|
| L1 | 연결 하나 = **서로 다른 두 성취기준의 키워드 하나씩, 모두 2개**. 세 성취기준이 함께 이어지면 연결 2개로 나눈다. 같은 키워드를 여러 연결에 다시 사용해도 된다 | "과목 A · 키워드 · 키워드 · 과목 B"로 그릴 수 있는 모양. 근거도 두 말 사이의 한 주장으로 분명해진다 |
| L2 | 종류는 두 가지. **same**: 두 키워드가 같은 현상이나 대상을 다룬다(집중호우 × 도시화 → 도시 침수 위험). **method**: 한 성취기준의 활동으로 다른 성취기준의 내용을 다룬다(발표 × 대처 방안 → 재해 대응 발표) | 교과 간 연결은 대부분 이 두 경우다. method를 명시하지 않으면 "논증하는 글"처럼 활동 성취기준이 잘못 고립된다 |
| L3 | 연결 이름: 학생이 실제로 다룰 대상이 드러나는 **2~10자 명사구**. 두 키워드 중 하나를 그대로 이름으로 삼지 않는다. '융합', '탐구', '소통', '문제 해결', '연계'처럼 어디에나 붙는 말 금지 | 이름은 카드의 축 표시로 다시 사용되므로 무엇을 다루는지 드러나야 한다 |
| L4 | 근거: **40자 이내 한 문장**. 두 키워드를 한 활동에서 어떻게 함께 다루는지 쓴다. "둘 다 ~와 관련된다"는 근거가 아니다. 번호 대신 교과명 | 근거가 교사가 지어낸 연결을 걸러 내는 유일한 장치다 |
| L5 | 낱말이 같아도 교과마다 뜻이 다르면 잇지 않는다(물리의 '일'과 일상어 '일') | 동음이의 연결 방지 |
| L6 | 같은 두 성취기준 사이 연결은 **1개, 꼭 필요할 때 2개까지**. 전체 **0~6개** | 그래프 가독성과 연결의 질 |
| L7 | 억지 연결 금지. 모든 키워드를 엮을 필요는 없다. 다만 발표·토의·글쓰기처럼 활동을 다루는 성취기준은 method 연결이 가능한지 먼저 살핀다 | 억지 연결을 막되 정당한 연결을 놓치지 않는다 |
| L8 | **서로 다른 성취기준 쌍을 고루 검토한다.** 프롬프트에 가능한 쌍 전체(S1-S2, S1-S3, …)를 나열하고 쌍마다 성립하는 연결이 있는지 따진다. 한 성취기준이 연결의 끝으로 몰리면, 그 성취기준이 없는 쌍을 다시 검토한 뒤에만 그 성취기준의 연결을 더한다. 예: 재난 조합(T2)에서 지구과학이 세 연결의 끝이 되었다면, 한국지리 탐구 '도시화' ↔ 인공지능 수학 '빅데이터'(도시 변화를 빅데이터로 살핀 사례 찾기), 화법과 언어 '발표' ↔ 한국지리 탐구(조사한 하천 변화 발표)처럼 지구과학이 없는 쌍이 실제로 성립하는지 먼저 검토한다 | 쏠림은 그래프에서 한 과목을 중심처럼 보이게 하고, 교사가 다른 과목끼리의 연결 가능성을 보지 못하게 한다(사용자 결정 14) |
| L9 | **우선순위: L7(억지 금지) > L8(고른 분산).** 다른 쌍이 성립하지 않으면 쏠린 결과를 그대로 둔다. 고르게 만들려고 근거가 약한 연결을 만들지 않는다 | 분산 때문에 지어낸 연결이 생기면 R3·R4 위험이 커진다 |

### 2-4. 연결되지 않은 성취기준 처리

- 연결되지 않은 성취기준은 **모델의 답을 믿지 않고 서버가 계산한다**(검증을 통과한 연결에 한 번도 등장하지 않은 성취기준).
- 그래프에서 숨기지 않는다. 자기 키워드와 함께 덩어리로 표시하고 `연결된 키워드 없음`을 붙인다.
- 카드에서는 그 성취기준을 활동(발표·글쓰기 등)으로만 가볍게 다루거나 "비중이 작은 성취기준"으로 밝힌다(§4-5). 그래프와 카드가 서로 다른 말을 하지 않게 한다.
- 연결이 0개면 상태 문장을 보이고(§6-4), 카드는 성취기준 원문만으로 만든다.

### 2-5. 서버 검증 (모델 응답 → 화면 데이터)

순서대로 적용한다.

| 순서 | 검사 | 처리 |
|---|---|---|
| V1 | JSON 추출 | 응답에서 가장 바깥 `{…}`를 파싱. 실패하면 1회 다시 생성, 두 번째도 실패하면 오류 |
| V2 | 키워드 원문 대조 | 공백·문장부호·가운뎃점(`·⋅ㆍ`)·괄호·따옴표를 지운 키워드가 같은 방식으로 지운 그 성취기준 원문에 부분 문자열로 들어 있어야 한다. 아니면 버린다 |
| V3 | 길이 | 지운 뒤 2자 미만이면 버린다. 표시용 원문은 16자에서 자른다 |
| V4 | 일반어 | 키워드가 정확히 다음 중 하나면 버린다: 자료, 사례, 방법, 내용, 과정, 문제, 탐구, 이해, 설명, 활동 |
| V5 | 조사 꼬리 | `의`, `을`, `를`, `에서`, `으로`, `에게`로 끝나면 버린다 |
| V6 | 꾸밈 조각 | "적"으로 끝나고, 원문에서 그 바로 뒤 글자가 `·`, `⋅`, `ㆍ`, `,` 가운데 하나면 버린다 |
| V7 | 같은 성취기준 안 중복 | 앞서 남긴 키워드와 같거나, 그것을 포함하거나, 그것에 포함되면(공백 무시) 버린다 |
| V8 | 키워드 개수 | 성취기준마다 앞에서부터 최대 4개. 모든 성취기준에서 키워드를 하나도 못 건지면 결과 없음(오류) |
| V9 | 연결 끝 | `ends`가 **정확히 2개**이고, 서로 다른 두 성취기준이며, 각 끝의 낱말이 V2~V8을 통과한 그 성취기준의 키워드와 같아야 한다. 아니면 그 연결을 버린다 |
| V10 | 연결 이름 | 빈 이름·이미 나온 이름이면 버린다. 표시용은 20자에서 자른다 |
| V11 | 종류 | `kind`가 `same`·`method`가 아니면 `same` |
| V12 | 상한 | 같은 두 성취기준 사이 최대 2개, 전체 최대 6개(먼저 온 것 우선) |
| V13 | 근거 | 본문에 남은 `S1` 같은 번호는 `{과목} {코드}`로 바꾼다. 60자를 넘으면 문장 경계에서, 없으면 공백에서 자른다 |
| V14 | 연결되지 않은 성취기준 | V9~V12를 통과한 연결에 등장하지 않은 성취기준 목록을 서버가 만든다 |
| V15 | 쏠림 기록(거르지 않음) | 연결이 2개 이상일 때 "가장 많은 연결의 끝이 된 성취기준의 비율"과 "서로 다른 성취기준 쌍의 수"를 로그로 남긴다. 이 값으로 다시 생성하거나 연결을 지우지 않는다(L9). §8-2 측정에 사용 |
| V16 | 연결 순서 | 근거 목록·가운데 칸에 보일 순서를 정한다. 같은 성취기준이 연달아 나오지 않게 가능한 범위에서 섞고, 그 밖에는 응답 순서를 따른다 |

화면 데이터 형식:

```json
{
  "keywords": { "{key}": ["원문 키워드", "…"] },
  "concepts": [
    { "label": "연결 이름", "kind": "same", "ends": [{ "key": "{key}", "word": "키워드" }, { "key": "{key}", "word": "키워드" }], "why": "근거 한 문장" }
  ],
  "isolated": ["{key}"]
}
```

### 2-6. 생성 조건

- 모델: Claude Sonnet 5.5(`claude-sonnet-5-5`), 최대 출력 3,000토큰, 생각 깊이 기본 `low`. 구현 후 §8 표본 조합에서 `low`와 `medium`의 키워드 결함 수를 비교해 결함이 뚜렷이 줄면 `medium`으로 올린다. 연결 찾기는 성취기준을 고르는 동안 뒤에서 돌기 때문에 몇 초 늘어나도 체감 대기가 거의 늘지 않는다.
- 캐시: 조합(정렬한 key 목록)마다 한 번 생성하고 모델 선택과 무관하게 공유한다. 같은 조합의 동시 요청은 첫 생성을 공유한다. 캐시 키 접두는 기존 캐시와 섞이지 않는 새 값(`bridge:v3:`).
- 실패해도 카드 생성은 막지 않는다(카드는 연결 지도 없이 만든다).

### 2-7. 그래프가 내용상 지켜야 할 것 (모양은 2부(디자인))

| 번호 | 요구 |
|---|---|
| G1 | 각 성취기준은 과목명(괄호 앞까지 줄인 이름) + 코드로 표시한다. 같은 과목이 2개 이상 골라졌을 때도 코드로 구분된다. 색은 교과군 색(3D와 같은 값) |
| G2 | **키워드가 그래프에서 가장 큰 글씨다** |
| G3 | 키워드(원문)와 연결 이름(AI가 붙인 이름)은 **모양이 달라야 하고** 범례로 밝힌다 |
| G4 | 키워드의 소속은 선 없이(바큇살 금지) **가까움과 교과색**으로 보인다. 모든 키워드는 다른 과목 이름보다 자기 과목 이름에 더 가깝다. 연결된 키워드는 자기 덩어리 안, 상대 과목을 향한 가장자리에 둔다 |
| G5 | 같은 키워드가 연결 2개에 사용되면 한 번만 그리고 선이 거기서 나뉜다 |
| G6 | 연결에 들지 않은 키워드는 자기 덩어리 안에 작게 남는다. 지우지 않는다(그 성취기준이 무엇을 다루는지, 왜 이어지지 않는지 판단하는 재료) |
| G7 | 연결되지 않은 성취기준은 숨기지 않고 `연결된 키워드 없음`을 붙인다 |
| G8 | **선 하나가 곧 연결 하나로 읽힌다.** 선은 키워드에서 키워드로만 긋고, 연결 이름은 그 선의 가운데에 붙인다. 선이 키워드·과목 이름 글자 위를 지나지 않는다. 연결 이름끼리, 연결 이름과 키워드는 겹치지 않는다 |
| G9 | 근거는 그래프 밖 **연결 근거 목록**에 항상 보인다(툴팁에만 두지 않는다). 목록 한 줄을 가리키거나 포커스하면 그래프의 그 연결이, 그래프의 연결을 가리키면 목록의 그 줄이 강조된다. 목록은 그래프의 텍스트 대안이다 |
| G10 | 연결 종류(same/method)가 그래프와 목록에서 구분된다(목록에서는 글자 꼬리표) |
| G11 | 같은 조합은 늘 같은 그림이다(난수 시드 고정). 연수에서 강사가 위치로 가리켜 설명하려면 모든 교사의 화면이 같아야 한다 |
| G12 | **모든 과목을 대등하게 보인다.** 과목마다 연결 수를 표시하지 않고, 연결 수에 따라 크기·밝기·위치(가운데 배치 등)를 바꾸지 않는다. 쏠림이 남은 조합에서는 한 과목에서 선이 여러 개 나가는 것만으로 사실이 드러나며, 그 이상 강조하지 않는다 |

| index | 이름 | 장면(프롬프트) | 학생 결과물(프롬프트) | 한 줄 설명(툴팁) |
|---|---|---|---|---|
| 0 | 학교 생활 | 학생이 학교 안의 공간·규칙·일과를 관찰하고 개선안을 학교 안에서 시범 운영하는 수업 | 시범 운영 결과 기록, 학교 안내물, 학생회 건의문 가운데 하나 | 학교 안 공간·규칙 개선 |
| 1 | 지역 문제 | 학생이 학교 밖 지역 현장(동네·지역 기관·시설)에 나가 조사하고 그 결과를 지역에 전달하는 수업 | 현장 조사 지도, 지역 기관에 보내는 제안서, 주민 안내 자료 가운데 하나 | 지역 현장 조사와 제안 |
| 2 | 지구적 문제 | 여러 나라의 자료와 국제 사례를 비교해 지구적 문제를 이해하고 세계 시민의 관점에서 판단하는 수업 | 국가 간 비교 자료, 세계 시민 관점의 해설문이나 발표 가운데 하나 | 국가 간 자료 비교 |
| 3 | 창작 프로젝트 | 배운 내용을 작품으로 만들어 표현하는 수업 | 영상·음악·전시·이야기·디자인·게임 가운데 하나 | 작품으로 표현 |
| 4 | 진로·직업 | 학생이 실제로 있는 직업의 역할을 맡아 그 직업의 업무 과정을 수행하는 수업 | 그 직업이 실제로 만드는 산출물(기획안·진단서·설계도·보도자료 등) | 직업인의 역할 수행 |
| 5 | 데이터 탐구 | 학생이 직접 수집하거나 공개된 자료를 정리하고 분석해 패턴을 찾는 수업 | 그래프와 해석을 담은 분석 보고서나 대시보드 | 자료 수집과 분석 |
| 6 | 과학 탐구 | 가설을 세우고 실험·관찰·조사로 확인하는 수업(과학 교과가 없는 조합이면 가설과 검증의 순서만 빌린다) | 탐구 설계와 결과를 담은 탐구 보고서 | 가설 세우기와 검증 |
| 7 | 역사적 관점 | 과거의 자료(기록·신문·작품·통계)를 오늘과 비교해 변화를 살피는 수업 | 연표나 과거와 현재의 변화 비교 해설 | 과거와 오늘 비교 |

- 결과물을 "가운데 하나"로 고르게 해 회차·조합이 달라도 같은 결과물(예: 지도와 제안)로 몰리지 않게 한다.
- 이름은 사용자가 고른 그대로다. 관점에는 색을 붙이지 않는다. 이 화면에서 색이 뜻하는 것은 교과군 하나뿐이다(관점 색이 국어 빨강·수학 파랑과 겹치면 교과로 오해한다). 구분 단서가 필요하면 단색 아이콘을 사용한다(2부(디자인)).

### 3-2. 순서와 배치 (3×3, 가운데 = 이번 조합의 연결)

```
┌──────────────┬──────────────┬──────────────┐
│ 0 학교 생활     │ 1 지역 문제     │ 2 지구적 문제    │  장소: 가까운 곳에서 먼 곳으로
├──────────────┼──────────────┼──────────────┤
│ 3 창작 프로젝트  │ 이번 조합의 연결  │ 4 진로·직업     │  만들기 · 역할 수행
├──────────────┼──────────────┼──────────────┤
│ 5 데이터 탐구    │ 6 과학 탐구     │ 7 역사적 관점    │  탐구 방법
└──────────────┴──────────────┴──────────────┘
```

- 근거: 격자는 행 단위로 읽힌다. 위 줄은 학교 → 지역 → 세계로 넓어지는 장소(사회과의 환경 확대 순서라 교사에게 설명이 필요 없다), 아래 줄은 탐구 방법이다. 줄 이름은 화면에 표시하지 않는다.
- 3×3을 택한 이유: 카드 폭이 넓어 최악 길이에서도 8장 모두 제목+설명 4줄로 사용자 결정 4(4~5줄)를 지킨다. 4×2는 카드 폭이 좁아 제목이 두 줄로 꺾이며 8장 중 5장이 6줄이 된다(디자인 2차 실측). 150% 배율 노트북에서 약 30px 넘치는 것보다 줄 수 규칙이 우선이다.
- 가운데 칸은 8장이 공유하는 바탕, 즉 **이번 조합의 연결 목록**이다(§4-6). 카드까지 내려오면 그래프가 화면 밖에 있으므로 카드 옆에서 연결을 다시 확인하게 한다.
- 좁은 화면(2열·1열)에서는 가운데 칸을 맨 앞에 두고 index 순서로 놓는다.
- index 8~29는 같은 관점의 다음 회차다(`index % 8`이 관점, `floor(index / 8) + 1`이 회차). "다른 아이디어"(P2)에서 사용한다.

## 4. 카드 내용 규칙

### 4-1. 카드 구성 순서 (위에서 아래로)

```
학교 생활                                       ← 관점 이름
학교 주변 배수로 점검표와 개선 건의문              ← 제목: 소재 + 결과물 (1줄)
집중호우 뒤 교내 배수로와 운동장 물웅덩이를 기록한다.  ← 활동 문장 ┐ 한 문단으로 이어 쓴다
도시화로 바뀐 학교 주변 지형과 함께 학생회 건의문으로 낸다. ← 결과물 문장 ┘ (축 키워드 강조)
연결: 도시 침수 위험                              ← 축 (있을 때만)
비중이 작은 성취기준: 인공지능 수학                 ← 있을 때만
                                  [프로젝트 시작]
```

- 본문(제목+설명)은 4~5줄. 연결 줄과 비중 줄은 짧은 정보 줄이다.
- 근거: 교사가 "괜찮다"고 느끼는 순간은 **장소·행동·결과물·대상이 구체적일 때**다. 제목을 결과물로 끝내면 수행 과제가 첫 줄에 보이고, 교사는 "우리 학생이 이걸 만들 수 있나"를 바로 판단한다. 교과가 만나는 지점은 문장으로 설명하지 않고 설명 속 키워드 강조와 연결 줄로 보여 준다.

### 4-2. 제목

- 소재와 학생 결과물이 드러나는 **명사구, 22자 이내, 결과물 이름으로 끝낸다**(지도, 제안서, 건의문, 보고서, 영상, 연표, 해설문, 브리핑 자료 등).
- "우리 동네", "우리 학교", "우리 반"으로 시작하지 않는다.
- 물음표·느낌표·쌍점(:) 금지. "읽기·그리기"처럼 비유로 사용한 동사로 끝내지 않는다.

### 4-3. 설명 (활동 문장 + 결과물 문장)

| 필드 | 규칙 |
|---|---|
| `activity` | 한 문장, 40자 이내. 학생이 **어디서 무엇을 조사하거나 만드는지** 장면으로. 주어 "학생들이"는 생략 |
| `product` | 한 문장, 40자 이내. **결과물을 누구에게 어떻게 내놓는지** |
| 공통 | "~한다"로 끝나는 평서문. 축으로 고른 연결의 키워드를 **원문 그대로 1개 이상** 넣는다. 차시·단계·평가 방법·자료 목록 금지. 성취기준 문장의 표현을 그대로 옮겨 적지 않는다 |
| 화면 | 두 문장을 한 문단으로 이어 보인다(`pitch` = `activity` + 공백 + `product`). 프로젝트 설명 추천에도 `pitch`를 사용한다 |
| 키워드 강조 | 그 카드 축 연결의 키워드가 설명에 **원문 그대로**(공백 차이만 무시) 들어 있을 때만 강조한다. 비슷한 말·활용형을 추측해 강조하지 않는다 |

### 4-4. 축(연결) 표시

- 카드 표시: `연결: {연결 이름}, {연결 이름}`(최대 2개, 그래프·근거 목록의 이름과 같은 문자열). 이름 앞 표시 모양으로 종류(same/method)를 구분한다(2부(디자인)).
- 축 배정: 서버가 카드마다 **먼저 검토할 연결**을 돌려 가며 정한다. `preferred = concepts[index % concepts.length].label`. 관점과 맞지 않으면 모델이 다른 연결을 고를 수 있다. 연결이 3개인 조합이면 8장이 연결 3개에 나뉘어 "같은 조합, 다른 수업"이 보인다.
- 완성된 카드들의 축 집합이 모두 같으면 카드에서 연결 줄을 숨기고 가운데 칸에 `여덟 아이디어 모두 ‘{연결 이름}’ 연결을 사용합니다.`를 적는다.
- 연결이 0개인 조합이면 축이 없고 연결 줄도 없다.

### 4-5. 비중이 작은 성취기준

- 모델은 `light`에 그 카드에서 활동이 거의 없거나 빠진 성취기준 번호(S1 등)를 적는다. 모두 다루면 빈 배열.
- 화면: `비중이 작은 성취기준: {과목명}`. 여럿이면 쉼표로 잇는다. 같은 과목이 2개 이상 골라져 있으면 `{과목명} {코드}`.
- 근거: 교사에게 필요한 것은 "내 성취기준이 이 아이디어에 다 들어가는가"라는 사실이다. 자유 서술 메모("솔직한 메모")는 거의 모든 카드에 붙어 변명처럼 읽혔고, 내용도 대부분 이 정보였다. 억지 연결은 만들지 않는 것이 원칙이므로 억지 연결을 고백하는 칸은 두지 않는다.

### 4-6. 가운데 칸 "이번 조합의 연결"

- 제목: `이번 조합의 연결`
- 연결마다 한 줄: 연결 이름 + 양 끝 과목명(교과색 표시). 근거 문장은 넣지 않는다(근거 목록에 있다).
- 연결되지 않은 성취기준이 있으면: `연결되지 않은 성취기준: {과목명}`
- 연결 0개: `이어지는 키워드를 찾지 못했습니다.`
- 축이 모두 같으면 위 §4-4 문장을 제목 아래에 둔다.
- (P1) 카드를 가리키면 가운데 칸에서 그 카드의 연결이 강조되고, 가운데 칸의 연결을 가리키면 그 연결을 사용한 카드가 강조된다.

### 4-7. 서버 검증과 다시 생성 조건

| 순서 | 검사 | 처리 |
|---|---|---|
| C1 | JSON 추출, `title`·`activity`·`product`가 비어 있지 않은 문자열 | 실패하면 다시 생성. 두 번째도 실패하면 오류 |
| C2 | 번호 치환 | 본문에 남은 `S1` 같은 번호는 `{과목} {코드}`로 바꾼다 |
| C3 | 주어 정리 | `activity`가 "학생들이 " 또는 "학생들은 "으로 시작하면 그 말을 지운다 |
| C4 | 축 | `axis`의 이름 가운데 그 조합의 연결 이름과 정확히 같은 것만 남긴다. 최대 2개 |
| C5 | 비중 | `light`의 유효한 번호만 성취기준 key로 바꿔 `light_keys`로 둔다(중복 제거) |
| C6 | 다시 생성 조건(첫 시도에만) | ① `pitch`가 120자 초과 ② 제목이 30자 초과 ③ `light_keys`가 고른 성취기준 수의 절반 초과(2개 조합에서 1개가 빠진 경우 포함) |
| C7 | 두 번째 시도 | C1만 통과하면 받아들인다. **문장을 중간에서 자르지 않는다.** 단 `pitch`가 200자를 넘는 비정상 응답만 마지막으로 끝난 문장까지 남긴다 |

화면 데이터 형식:

```json
{
  "index": 0, "lens_label": "학교 생활",
  "title": "…", "activity": "…", "product": "…", "pitch": "activity + ' ' + product",
  "axis": ["연결 이름"], "light_keys": ["{key}"],
  "model": "claude-sonnet-5-5", "keys": ["{key}", "…"]
}
```

### 4-8. 생성 조건

| 모드 | 모델 | 최대 출력 | 생각 깊이 |
|---|---|---|---|
| 빠른(기본) | Claude Sonnet 5.5 `claude-sonnet-5-5` | 2,000토큰 | medium |
| 정밀 | Claude Opus 5.5 `claude-opus-5-5` | 6,000토큰 | medium |

- "미래 보기"를 누르면 관점 8개(index 0~7)를 한꺼번에 요청하고 준비되는 대로 채운다. 보는 중에 모델을 바꾸면 그 모델로 8개를 요청한다(이미 만든 것은 그대로).
- 캐시: (모델, 정렬한 조합, index)마다. 같은 요청의 동시 생성은 공유한다. 캐시 키 접두는 기존 캐시와 섞이지 않는 새 값(`future:v6:`).
- 거절 응답이면 오류 422(문구 §6-7), 그 밖의 실패는 502.

### 4-9. 카드 동작

| 동작 | 내용 |
|---|---|
| 프로젝트 시작 | 고른 성취기준을 담기 목록에 넣고, 제목 추천 = `title`, 설명 추천 = `pitch`로 프로젝트 만들기 화면으로 이동한다 |
| 성취기준 담기 | **카드가 아니라 결정 줄에 하나.** 고른 성취기준 key를 설계 모드·3D·프로젝트 만들기와 공유하는 담기 목록에 넣는다. 카드마다 두면 아이디어를 담는 것으로 오해한다 |
| 다시 만들기 | 오류 카드에서 같은 index를 다시 요청한다 |
| 다른 아이디어(P2) | 같은 관점의 다음 회차(index + 8, 최대 29)를 요청한다. 앞뒤 이동은 `아이디어 {i}/{n}` |

## 5. 프롬프트 원문

`{…}`는 서버가 채우는 값, `[조건: …]`은 그 조건일 때만 넣는 블록이다. 성취기준은 프롬프트 안에서 `S1`부터 순서대로 번호를 붙인다.

### 5-1. 연결 찾기

```
교사가 고른 성취기준 {n}개를 하나의 수업으로 엮으려고 합니다. 먼저 성취기준마다 키워드를 고르고, 서로 다른 두 성취기준의 키워드 가운데 한 수업에서 실제로 함께 다룰 수 있는 것만 연결해 주세요.

## 고른 성취기준
S1. {code} [{subject}] {content}
S2. {code} [{subject}] {content}
…

## 검증된 교과 연결
[조건: 있으면] - S1-S2 / 주제: {integration_theme} / 근거: {rationale}
[조건: 없으면] - 없음

## 검토할 성취기준 쌍
{S1-S2, S1-S3, S2-S3, … 가능한 쌍 전체}

## 키워드 원칙
1. 성취기준마다 키워드를 3~4개 고르세요. 그 성취기준이 다루는 대상·개념 2~3개와, 학생 활동을 나타내는 명사 0~1개(예: 토의, 발표, 논증하는 글, 조사)로 구성합니다.
2. 키워드는 성취기준 원문에 있는 말을 그대로 옮기세요(2~12자). 고치거나 바꿔 말하지 마세요. 원문에서 뜻이 서는 가장 짧은 구절을 고르세요(예: '신체적, 정신적 질환 예방'보다 '질환 예방').
3. 가운뎃점(·)이나 쉼표로 묶인 말에서 꾸미는 말만 떼어 내지 마세요. '준언어적'이 아니라 '준언어적·비언어적 표현'처럼 꾸밈을 받는 말까지 옮기세요.
4. 다음은 키워드가 아닙니다.
   - 행동만 나타내는 말: 설명할 수 있다, 탐구한다, 이해하고, 파악한다
   - 어느 성취기준에나 있는 말: 자료, 사례, 방법, 내용, 과정, 문제, 탐구
   - 조건이나 꾸밈만 담은 말: 자신의 수준, 활용한 사례
5. 한 성취기준 안에서 뜻이 겹치는 키워드는 하나만 고르세요(예: '식생활문화'와 '건강한 식생활 문화' 가운데 하나).

## 연결 원칙
6. 연결 하나는 서로 다른 두 성취기준의 키워드를 하나씩, 모두 2개 잇습니다. 세 성취기준이 함께 이어지면 연결 2개로 나눠 적으세요. 같은 키워드를 여러 연결에 다시 사용해도 됩니다.
7. 연결은 두 종류만 만드세요.
   - same: 두 키워드가 같은 현상이나 대상을 다룹니다. 예: 집중호우 × 도시화 → 도시 침수 위험
   - method: 한 성취기준의 활동으로 다른 성취기준의 내용을 다룹니다. 예: 발표 × 대처 방안 → 재해 대응 발표
8. 연결 이름은 학생이 실제로 다룰 대상이 드러나는 2~10자 명사구로 쓰세요. 두 키워드 가운데 하나를 그대로 이름으로 삼지 마세요. '융합', '탐구', '소통', '문제 해결', '연계'처럼 어디에나 붙는 말은 사용하지 마세요.
9. why는 40자 이내 한 문장으로, 두 키워드를 한 활동에서 어떻게 함께 다루는지 쓰세요. '둘 다 ~와 관련된다'는 이유가 되지 않습니다. 번호 대신 교과명을 쓰세요.
10. 낱말이 같아도 교과마다 뜻이 다르면 잇지 마세요(예: 물리의 '일'과 일상어 '일').
11. 같은 두 성취기준 사이의 연결은 1개, 꼭 필요할 때만 2개까지 만드세요. 전체 연결은 0~6개입니다.
12. 모든 키워드를 엮을 필요는 없습니다. 억지스러운 연결은 만들지 마세요. 이어지지 않는 성취기준은 그대로 둡니다. 다만 발표·토의·글쓰기처럼 활동을 다루는 성취기준은 method 연결이 가능한지 먼저 살펴보세요.
13. '검토할 성취기준 쌍'을 하나씩 모두 살펴 성립하는 연결이 있는지 따지세요. 연결이 한 성취기준에 몰리지 않게, 그 성취기준이 들어가지 않은 쌍을 먼저 검토한 뒤에 그 성취기준의 연결을 더하세요.
14. 12번이 13번보다 우선합니다. 다른 쌍에서 실제로 성립하는 연결이 없으면 한 성취기준에 연결이 몰려도 그대로 두세요. 고르게 만들려고 근거가 약한 연결을 만들지 마세요.

### 6-8. 바닥 안내

키워드 연결과 수업 아이디어는 AI가 성취기준 원문을 바탕으로 만든 것입니다. 키워드는 원문에 있는 말만 사용하고, 이어지지 않는 성취기준은 억지로 잇지 않습니다. 수업에 사용하기 전에 성취기준 해설과 함께 확인해 주세요.

### 6-9. 금지어

미래 보기 기능의 화면 문자열(JSX 텍스트·aria·title·서버 오류 문구, 진입 버튼 포함)에서 다음을 사용하지 않는다. 3D 화면의 이름 "교육과정 성운"처럼 다른 기능의 문구는 대상이 아니다: `자리`, `별자리`, `타임스톤`, `스톤`, `마방진`, `마법진`, `갈래`, `그리는`, `그리기`, `그리지`, `그립니다`, `꼭지`, `만나는 지점`, `성운`, `솔직한 메모`.
**키워드 데이터에는 적용하지 않는다.** 문학 성취기준의 "갈래"처럼 원문 용어가 키워드로 나올 수 있다.

1. 7개 조합 전체에서 원문에 없는 키워드 0, 조각·일반어·조건어 키워드 0, 같은 성취기준 안 중복 0.

### 8-2. 연결

3. 모든 연결의 끝이 정확히 2개. 같은 두 성취기준 사이 최대 2개, 전체 최대 6개.

6-1. 쏠림: T2·T7처럼 연결이 2개 이상인 조합에서 서로 다른 성취기준 쌍이 2개 이상이다. 한 성취기준이 모든 연결의 끝인 결과는 표본 검토(2인)에서 "다른 쌍에 실제로 성립하는 연결이 없다"고 판정될 때만 허용한다. 분산 때문에 생긴 근거가 약한 연결은 0개(항목 4·5와 같은 기준으로 판정). V15 로그로 조합별 "최다 끝 비율"을 기록해 규칙 도입 전후를 비교한다.

7. 1,280px 화면(3×3)에서 8장 중 7장 이상이 제목+설명 5줄 이내. 문장을 중간에서 자른 카드 0장.

### 1-1. 흐름과 섹션 표시 조건

```

### 2-2. 교과색을 쓰는 곳과 쓰지 않는 곳

| 쓰는 곳 | 방식 |
|---|---|
| 과목 덩어리 구름 | 방사형 그라디언트: 중심 알파 0.20 → 60% 지점 0.07 → 가장자리 0. 연결되지 않은 성취기준은 0.11 → 0.04 → 0 |
| 행성(과목 표식) | 반지름 18 원, **모든 과목 같은 크기**. 채움은 방사형 그라디언트(중심 36%·32%, 반지름 72%): 0 = 교과색과 흰색 50% 섞음, 0.55 = 교과색, 1 = 교과색과 `#04060F` 55% 섞음(구체처럼 보이게). 바깥에 반지름 29 알파 0.13 후광 원. 필터 없음 |
| 연결된 키워드 알약 | 바탕 = 교과색 10%, 테두리 = 교과색 50%. 글자는 늘 `#F1F5F9` |
| 위성(연결 안 된 키워드) | 반지름 4.5 교과색 채움 + 왼쪽 위로 1.3px 옮긴 반지름 1.6 흰색 알파 0.45 점(작은 구체 느낌) |
| 연결된 키워드 알약 안의 위성 | 알약 왼쪽 여백 13px 뒤에 같은 위성 원(반지름 4.5) |
| 입력 칩·검색 결과·근거 목록·가운데 칸의 과목 점 | 지름 7~10px 원. 입력 칩의 점만 `box-shadow: 0 0 8px {교과색}`(정지) |

| 쓰지 않는 곳 | 이유 |
|---|---|
| 연결선·연결 이름·종류 표시 | 연결은 두 교과 사이의 것이라 한쪽 색을 칠하면 소속을 잘못 알린다. 만남 색 하나 |
| 관점(카드 머리) | 색 체계는 교과군 하나뿐(관점 색이 교과색과 겹치면 교과로 오해한다). 관점은 단색 아이콘 + 이름 |

| 키워드 글자 | 노랑(사회)·보라(음악) 글자는 가독성이 교과마다 달라진다. 글자는 t1 |

### 2-3. 타이포그래피

글꼴은 `.futures-root { font-family: 'Nanum Gothic', var(--font-sans); }`. 3D 쇼케이스와 같은 글꼴이고, 운영체제마다 글자 폭이 같아야 그래프 배치(글자 폭 측정)가 맞는다. 굵기는 400·700·800만 있다. 코드는 `ui-monospace, Menlo, Consolas, monospace`. 숫자가 바뀌는 곳은 `tabular-nums`, 한글 문단은 `word-break: keep-all`.

| 역할 | 크기/굵기/행간 | 색 |
|---|---|---|
| 화면 제목 | 22 / 800 | t1 |
| 화면 소개 | 14 / 400 / 1.6, 최대 폭 760px | t2 |

## 3. 연결 그래프

### 3-1. 모양 원칙

- 그래프는 3D 교육과정 성운을 위에서 내려다본 2D 지도다. 과목마다 교과색 구름 하나가 **가로로 넓은 바깥 링** 위에 떠 있고, 링은 화면 중심 둘레 **360° 전 방향**을 쓴다. 각도·반지름을 결정적 시드로 흔들어 정다각형·좌우 대칭·세로 축 정렬로 보이지 않게 한다.
- **모든 과목은 대등하다.** 연결이 많은 과목도 링 위의 한 칸이며 가운데로 들어오지 않는다. 과목 표식(점·이름 글자) 크기는 연결 수와 무관하게 같다.
- **가운데는 비운다.** 가운데 공간은 연결선과 연결 이름만 지나간다.
- **과목 = 행성, 키워드 = 위성.** 덩어리 가운데에 교과색 구체(행성)와 그 아래 과목 이름·코드가 있고, 키워드는 모두 그 행성에 딸린 위성이다. 연결 안 된 키워드는 행성 가까이 불규칙한 거리·각도에 떠 있는 작은 위성(원 + 읽히는 글자)이고, 연결된 키워드는 같은 위성을 알약으로 강조해 **상대 과목을 향한 가장자리**에 둔다. 위성은 움직이지 않는다(공전·회전 없음).
- 행성과 위성 사이에는 선이 없다. 선은 **키워드 알약에서 키워드 알약으로만** 긋고, 안쪽 공간을 가로질러 먼 덩어리로 건너간다. 선 하나가 연결 하나이고, 연결 이름은 그 선의 가운데 부분 위에 붙는다.
- 연결된 과목끼리는 링에서 가능한 한 서로 멀리(마주 보게) 놓는다(배정 점수 = 연결 거리 합). 그래서 선과 연결 이름이 가운데 공간을 가로지른다.
- 한 성취기준이 모든 연결의 한쪽 끝인 조합(허브)은 데이터가 그런 것이다. 배치는 그 과목을 다른 과목과 같은 링 위·같은 크기로 두는 데까지 책임진다(데이터 쪽 완화는 §3-10).

### 3-3. 배치 알고리즘 (의사코드)

입력이 같으면(성취기준 **집합**·키워드·연결·폭이 같으면) 입력 순서와 관계없이 같은 좌표를 낸다. `Math.random`을 쓰지 않는다.

```js
// 입력: standards[{key, code, subject, subject_group}] (2~6개), bridges, W(패널 폭 px), measure(text, font) → 폭(px)
// 출력: { W, H, ok, clusters[], chains[], dust[] }  (모든 좌표는 px)
const P = { pad: 22, gap: 44, pillH: 34, pillH2: 54, pillPadX: 13, pillDot: 12, pillMaxText: 168,
            planetR: 18, satR: 4.5, satLimX: 205, satLimY: 104 }
const FONT = { kw: "700 16px 'Nanum Gothic'", cap: "700 13px 'Nanum Gothic'", name: "800 14.5px 'Nanum Gothic'",
               star: "400 13px 'Nanum Gothic'", code: "400 11.5px monospace", iso: "400 12px 'Nanum Gothic'" }

// ── ⓪ 결정적 난수 ──
keys  = standards의 key를 사전순 정렬                       // 입력 순서와 무관하게 만든다
seed  = FNV1a32(keys.join('|'))
rng(s) = mulberry32(s)                                    // 0~1 균등 난수 생성기
// 용도마다 다른 흐름: 칸 = rng(seed ^ 0x9E3779B9), 링 반지름 흔들림 = rng(seed ^ hash(key)),
//                     덩어리 안 = rng(hash(code)), 바탕 별 = rng(seed ^ 0x51ED27)

concepts = 끝이 정확히 2개이고 두 끝이 서로 다른 성취기준인 연결만
n = standards 수;  H = {2: 420, 3: 480, 4: 540, 5: 600, 6: 600}[n]

repeat grow = 0..4:                                       // 품질 조건을 못 채우면 H를 40씩 키워 다시
  // ── ① 360° 칸: 타원 둘레를 n등분하고 시드로 흔든다 ──
  a = W/2 - 165;  b = H/2 - 85;  R = rng(seed ^ 0x9E3779B9)
  θ0 = (n == 2) ? (200° + 22°·R()) : R()·(360°/n)          // 2과목은 왼쪽 위 ↔ 오른쪽 아래 대각선
  for i in 0..n-1:
    θi = θ0 + i·(360°/n) + (R() - 0.5)·0.44·(360°/n)       // 각도 흔들림 ±22% 칸
    ρi = 0.86 + 0.14·R()                                  // 반지름 흔들림(배정용 위치에만 사용)
    slot[i] = (θi, W/2 + a·ρi·cos θi,  H/2 + b·ρi·sin θi)

  // ── ② 과목 → 칸 배정: 연결된 쌍은 멀리, 선 교차는 적게 ──
  for perm in permutations(0..n-1) (사전순으로 생성, n! ≤ 720):
    at[keys[j]] = slot[perm[j]]
    score = Σ_{c ∈ concepts} |at[c.a] - at[c.b]|  -  60 × (끝을 공유하지 않는 두 연결의 직선 교차 수)   // 가로지르는 긴 선을 우선
  가장 큰 score 채택(같으면 먼저 생성된 perm)

  θ[k] = at[k].θ;   ρ[k] = 0.94 + 0.06·rng(seed ^ hash(k))()   // 링 반지름 흔들림 0.94~1.0
  pos[k] = at[k]의 좌표
  // ── ③~④ 덩어리 만들기와 바깥 링 배치: 3회 반복 ──
  ringPlace(k):                                           // 덩어리 범위가 그 방향의 화면 끝에 닿는 타원 위 점 × ρ
    bb = cluster[k].범위(이름 중심 기준 [x0, y0, x1, y1])
    A = W/2 - pad - (cos θ[k] ≥ 0 ? bb.x1 : -bb.x0)
    B = H/2 - pad - (sin θ[k] ≥ 0 ? bb.y1 : -bb.y0)
    pos[k] = (W/2 + A·ρ[k]·cos θ[k],  H/2 + B·ρ[k]·sin θ[k])
  repeat round = 0..2:
    for k in keys: cluster[k] = buildCluster(k, pos)        // ③ 상대 방향은 현재 pos로 계산
    for k in keys: ringPlace(k)                            // ④ 모두 링 위로
    repeat 최대 400회:                                     // 겹치면 링을 따라 각도만 벌린다(안쪽으로 들이지 않는다)
      for each pair (i, j) 의 범위 상자가 gap 44 안으로 겹치면:
        d = wrap(θ[j] - θ[i])  (0이면 i<j 쪽으로 아주 작은 값)
        θ[i] -= 0.012·sign(d);  θ[j] += 0.012·sign(d);  ringPlace(i); ringPlace(j)
      한 번도 움직이지 않았으면 중단

  // ── ⑤ 품질 판정 후 연결선 ──
  chains = routeEdges()                                    // ⑥·⑦
  ok = (덩어리 범위 겹침 0) and (위치를 못 찾은 알약 0) and (선이 글자를 지나는 경우 0) and (이름표 충돌 0)
  if ok: break
if not ok: 목록 모드로 표시(§3-8)

// ── ③ buildCluster(k, pos): 행성과 위성 배치 (좌표 원점 = 행성 중심) ──
R = rng(hash(code))
행성 상자 = 폭 max(이름, 코드, (고립이면) 연결되지 않음 표시, 2·planetR + 16)
           위 = -planetR - 4,  아래 = planetR + 38 (고립이면 + 16)          // 행성 + 아래 이름·코드
// 연결된 키워드 = 알약으로 강조한 위성: 상대 과목 방향 가장자리
for 알약 p (같은 성취기준·같은 낱말은 하나, 연결 여러 개면 공유):
  p.w = 글자 폭 + 2·pillPadX + pillDot
  φ = atan2( Σ_{p가 속한 연결 c} 단위벡터(pos[상대 과목] - pos[k]) )
for p in 알약들 (φ 오름차순, 같으면 낱말 사전순):
  for ring in 0..3, off in [0, +.22, -.22, +.44, -.44, +.66, -.66] (rad):
    f = φ + off
    rx = 행성상자폭/2 + 22 + p.w/2 + 46·ring
    ry = (sin f < 0 ? -행성상자위 : 행성상자아래) + 12 + p.h/2 + 40·ring
    후보 중심 = (rx·cos f, ry·sin f)
    거절: 이미 놓인 상자와 겹침(여유 8) / 다른 과목 중심이 자기 과목 중심보다 가까움(+24 여유)
    첫 통과 후보 채택
  (모두 거절이면 ring 0, off 0에 놓고 '못 찾음'으로 표시 → ⑤에서 품질 실패)
// 연결 안 된 키워드 = 위성: 행성 가까이, 연결 방향의 반대편부터 황금각 나선(같은 거리·같은 각도 없음)
back = (알약 있으면) atan2(Σ 알약 방향) + π  :  R()·2π
m = 0
for w in (그 성취기준 키워드 - 알약 낱말):
  최대 600회:
    r = planetR + 22 + 12·√(m+1)·(0.8 + 0.4·R());   θ = back + m·137.508°;   m += 1
    위성 중심 = (1.6·r·cos θ,  0.78·r·sin θ)              // 가로로 긴 타원 궤도, 거리마다 흔들림
    글자 쪽 = (x ≥ 0) ? 오른쪽 : 왼쪽                     // 행성에서 먼 쪽
    상자 = 위성 원(지름 9) + 간격 7 + 글자 폭(measure(w, '400 13.5px')),  높이 20, 여유 2
    거절: |x| > 205 또는 |y| > 104
          / 상자가 화면 가운데 타원(가로 반지름 0.18W, 세로 0.18H) 안에 들어감   // 가운데 비움
          / 놓인 상자와 겹침(여유 6)
          / 어떤 알약에서 그 방향으로 260px 뻗은 통로(선분)와 만남(상자 4px 확대)   // 나가는 선을 가리지 않게
    첫 통과 후보 채택
덩어리 범위 = 행성·알약·위성 상자의 합 + 12

// ── ⑥ routeEdges: 선이 글자 위를 지나지 않는 휨 고르기 ──
연결을 길이(두 알약 중심 거리) 내림차순으로 처리(같으면 이름 사전순)
for c in concepts:
  A0, B0 = 두 알약 경계점;  L = |B0 - A0|;  N = 단위 법선;  M = 중점
  out = 법선 중 화면 중심에서 멀어지는 쪽의 부호(0이면 hash(이름) 홀짝)      // 바깥으로 부푼 곡선부터 시도
  for f in [0, .1, -.1, .2, -.2, .3, -.3, .4, -.4]:
    ctrl = M + N·out·f·L
    곡선을 32구간으로 나눠, 자기 두 알약을 뺀 모든 글자 상자(3px 확대)와 만나는 구간 수 = lineHit
    ⑦ 이름표 후보 t ∈ [.5, .42, .58, .35, .65, .28, .72]:
      상자를 곡선 위 점 B(t)에 중심 맞춤
      capHit = 글자 상자(여유 3)·먼저 놓인 이름표(여유 4)와 겹치는 수
      비용 = lineHit·10 + capHit·100 + |f| + |t - .5|
    비용이 가장 작은 (f, t) 채택. lineHit = capHit = 0 이면 즉시 중단
  이름표 상자를 '놓인 이름표'에 추가

// ── 바탕 별 ──  rng(seed ^ 0x51ED27)로 46개 (x ∈ [0, W], y ∈ [0, H])
```

- `measure`는 `canvas.measureText`로 위 글꼴 문자열을 잰다. 첫 배치 전에 `document.fonts.ready`를 기다리고, 글꼴이 늦게 도착하면 한 번 더 배치한다. 단위 테스트에서는 `measure`를 주입한다(한글 1em, ASCII 0.56em).
- 계산은 (성취기준 집합, 연결 결과, 폭을 8px 단위로 반올림한 값)이 바뀔 때만 한다. 실측: 6과목·연결 6개 약 25ms.
- 연결이 0개이면 ② 점수가 모두 0이라 첫 순열이 선택되고, 모든 행성이 위성(연결 안 된 키워드)만 가진다.

### 3-4. 겹침·소속 규칙 (배치가 보장하고 테스트가 확인할 것)

| 규칙 | 보장 방법 |
|---|---|
| 글자 상자(과목 이름·키워드 알약·위성 글자) 사이 겹침 0 | 덩어리 안은 ③의 충돌 거절, 덩어리 사이는 ④의 링 위 각도 벌리기 + 품질 판정 |
| 가운데 비움 | ④가 모든 덩어리를 링(그 방향의 화면 끝에 닿는 위치 × 0.94~1.0)에 둔다. 가운데로 당기는 힘이 없다 |
| 이름표끼리, 이름표와 글자 겹침 0 | ⑦ capHit = 0 |
| 선이 키워드·과목 이름 글자 위를 지나지 않음 | ⑥ lineHit = 0 (자기 두 알약 제외) |
| 연결 이름은 그 선의 가운데 부분에 | t를 0.28~0.72로 한정 |
| 모든 알약은 다른 과목 이름보다 자기 과목 이름에 더 가깝다 | ③의 거절 조건 |
| 연결 안 된 키워드(위성)는 자기 행성 가까이 | ③ 위성 범위 \|x\| ≤ 205, \|y\| ≤ 104 |
| 위성 거리·각도 불규칙 | 황금각 + 거리 흔들림(0.8~1.2배). 같은 행성의 위성끼리 궤도 거리가 같지 않다 |
| 위성은 가운데 타원 밖 | ③ 거절 조건. 연결된 키워드 알약만 상대 방향으로 가운데 타원 경계에 닿을 수 있다 |
| 선끼리 교차 | 허용(근거 목록과 서로 강조로 구분) |

### 3-5. 상호작용

- **근거 목록 한 줄을 가리키거나 포커스** → 그 연결의 선이 `#7DD3FC` 2.25px, 양 끝 알약은 그대로, 다른 연결 묶음(선+이름표)은 불투명도 0.22, 다른 알약은 0.45. 목록의 다른 줄은 0.5.
- **그래프의 선·이름표·알약을 가리키면** 같은 강조 + 목록의 해당 줄 바탕 `rgba(255,255,255,.05)`. 알약이 연결 2개에 쓰이면 둘 다 강조한다.
- **과목 이름을 가리키면** 그 과목의 연결이 모두 강조된다.
- 전환은 불투명도·선 색만 150ms. 위치·크기는 바뀌지 않는다.
- 터치: 목록 줄이나 선을 누르면 강조가 고정되고, 빈 곳을 누르면 풀린다.

## 8. 접근성

- 그래프 SVG는 `aria-hidden="true"`. 연결 근거 목록이 텍스트 대안이다(각 줄 `tabIndex=0`, 포커스가 호버와 같은 강조).

- 카드 버튼 aria = `{1부 §6-6 카드 버튼 aria}`.
- 키보드 순서: 고르기 → 근거 목록 → 결정 줄 → 카드(index 순, 가운데 칸은 읽기만).

# 3부. 구현 구조

## T1. 진입과 라우트
- 진입: 워크스페이스 첫 화면 머리 버튼 "미래 보기" → `/futures`.
- 라우트: `/futures`, 로그인 필수(ProtectedRoute), 지연 로드 청크(다른 화면 번들에 영향 없음).
- URL이 상태를 기록한다: `/futures?codes=키1,키2,…&model=precise` (빠른 모드는 model 생략). 성취기준 식별자는 key(충돌 코드는 `코드|과목`). 새로고침·공유 시 같은 조합이 복원된다.

## T2. 서버 API (모두 로그인 필수)
| 메서드·경로 | 입력 | 출력 | 비고 |
|---|---|---|---|
| GET `/api/futures/catalog` | 없음 | `{ fields, rows }` 전체 성취기준 가벼운 행 `[key, code, subject, subject_group, school_level, curriculum_category, content]` | 메모리에 만든 문자열 재사용, `Cache-Control: private, max-age=600` |
| POST `/api/futures/bridges` | `{ codes: key[2..6] }` | `{ bridges, cached }` | 연결 찾기. 조합당 1회 생성·캐시, 모델과 무관 |
| POST `/api/futures` | `{ codes: key[2..6], model: 'fast'|'precise', index: 0..7 }` | `{ future, cached }` | 카드 1장. 같은 조합·모델·번호는 캐시 |

- 검증 실패 400(문구는 1부), 모델 거절 422, 생성·파싱 2회 실패 502, 그 밖 500(일반 문구). 미인증 401.
- `bridges` 형식: `{ keywords: { [key]: string[] }, concepts: [{ label, ends: [{ key, word }, { key, word }], kind, why }], isolated: key[] }` — 끝은 정확히 2개(서로 다른 성취기준), `kind`·`why` 규칙은 1부. `isolated`는 서버가 계산.
- `future` 형식은 1부 카드 규칙의 필드를 그대로 따른다(제목·문장들·축 연결·비중이 작은 성취기준 등). 서버는 문자열 길이·필수 필드를 검사하고 내부 번호(S1 등)를 교과명으로 바꾼다.

## T3. 생성 엔진
- 모델: 빠른 = `claude-sonnet-5-5`, 정밀 = `claude-opus-5-5`, 생각 깊이 `output_config.effort: 'medium'`(연결 찾기는 빠른 모델 `low`). 요청마다 timeout 150초(연결 90초), SDK 재시도 1회. `stop_reason: 'refusal'`이면 422.
- 응답은 JSON만. 파싱·검증 실패 시 1회 재생성, 그래도 실패면 502. 설명 길이 초과 시 처리 규칙은 1부(문장 중간 자르기 금지).
- 연결 찾기 검증(서버): 키워드는 해당 성취기준 원문의 부분 문자열(공백·가운뎃점·문장부호 무시 대조)만 남기고, 연결 끝은 검증된 키워드만, 같은 성취기준끼리 연결·중복 이름 제거, 이어지지 않은 성취기준 계산.
- 카드 생성은 연결 찾기 결과를 먼저 받아(같은 조합 진행 중이면 그 결과를 기다려 공유) 프롬프트에 넣는다. 연결 찾기가 실패해도 카드는 연결 없이 생성한다.

## T4. 캐시·중복 제거·부하 보호
- 캐시: Supabase `scenario_cache`(키 접두 `bridge:v3:` / `future:v6:` — 형식이 바뀌므로 버전 상향, 기존 시나리오 캐시 키는 `[`로 시작해 겹치지 않음) + 서버 메모리 600개(DB 장애 시에도 같은 조합 재생성 방지). 캐시 장애는 생성을 막지 않는다.
- 같은 키의 동시 요청은 첫 생성을 공유(in-flight dedupe).
- 서버 전체 동시 생성 상한 80(`FUTURES_QUEUE_CONCURRENCY`, 연수 최대 10명 × 8장). 채팅과 같은 API 키를 쓰므로 분당 출력 토큰 한도(200만)의 약 4분의 1 이하로 묶는다. 채팅 큐와 분리.
- 생성 요청(POST) 사용자당 분당 40회. 목록·조회(GET)는 일반 한도만.
- 실측 기준(2026-10-02): 카드 1장 ≈ 입력 1,750·출력 300~1,250토큰, 8장 + 연결 찾기 ≈ 9초(빠른 모드).

## T5. 화면 데이터 흐름
1. 진입 시 catalog 1회 로드(검색은 클라이언트에서: 코드 정규화 일치 우선, 띄어쓰기 무시 다중 낱말 AND, 학교급 필터, 코드 여러 개 붙여 넣기).
2. 성취기준 조합이 바뀌면(2개 이상) 0.7초 뒤 `POST /bridges`. 조합이 다시 바뀌면 늦게 온 결과는 버린다(조합 서명 비교). 그래프는 결과가 오면 바로 그린다("미래 보기" 전에 노출).
3. "미래 보기" 클릭 → 현재 모델로 8장을 한꺼번에 요청. 카드는 도착하는 대로 채운다(번호별 상태: 대기·생성 중(경과 초)·완료·오류+다시 시도).
4. 모델 전환: 이미 만든 카드는 모델별로 보관, 새 모델 카드가 없으면 8장 요청.
5. 조합 변경 시 카드 결과를 지우고 처음 상태로.
6. 담기·프로젝트 시작: 세션 저장소 `cw_design_basket`(key 배열)·`cw_design_basket_meta`(key→교과군)에 고른 성취기준을 더하고, 프로젝트 시작은 `cw_project_title_suggestion`·`cw_project_desc_suggestion`에 카드 제목·설명을 넣은 뒤 `/workspaces?createProject=1`로 이동(기존 프로젝트 만들기 흐름 재사용).

## T6. 코드 구성 원칙
- 페이지 1개 + 그래프 컴포넌트 1개 + 카드 묶음 컴포넌트 1개 + 순수 함수 모듈(검색·URL·그래프 배치 — 단위 테스트 대상).
- CSS는 페이지 루트 클래스 아래로만(다른 화면에 새지 않게), 키프레임은 접두사로 구분. 애니메이션 루프·리스너는 페이지를 떠나면 모두 정리.
- 디자인 토큰은 3D 성운 단일 소스(`nebulaTheme.js`)에서 가져오거나 같은 값을 쓴다.
