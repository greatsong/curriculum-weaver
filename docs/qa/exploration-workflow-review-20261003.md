# 탐색 기능 현황과 개선 계획

작성일: 2026년 10월 3일. 검토 기준: PR #145가 반영된 코드 `2ae5476`과 기존 프로젝트 연결 로직. 실제 교사 사용 관찰이나 이용 통계 분석은 수행하지 않았다. 아래 사용성 판단은 코드와 화면 구조에 근거한 전문가 검토이며, 개선 효과는 사용자 테스트로 확인해야 한다.

탐색의 강점을 유지하면서 **성취기준 찾기 → 수업 아이디어 검토 → 프로젝트에 반영**이라는 목적이 화면마다 이어지도록 정리할 것을 제안한다. 현재는 진입 버튼의 비중, 기능 이름, 결과를 프로젝트로 가져가는 방식이 서로 달라 사용자가 다음 행동을 판단하기 어렵다.

**일정과 변경 범위**

사용자 최종 결정: 탐색 기능 개선은 버튼 이름·배치, 프로젝트 문맥, 검토·저장 상태 안내까지 모두 연수 전에 진행한다. 안정성을 위해 구버전 기능 코드의 실제 삭제만 연수 후로 미룬다. 2026년 10월 11일 오전 9시 한국 시간에 이 대화에서 구버전 코드 삭제 검토를 시작해야 한다고 알려주는 알림을 등록했다. 알림이 자동 삭제나 배포를 실행하지는 않는다. 이번 구현·검증 결과는 별도 QA 기록으로 남긴다.

**현재 탐색 기능과 사용자에게 설명할 역할**

| 현재 기능 | 사용자에게 안내할 용도 | 현재 프로젝트 연결 방식 |
| --- | --- | --- |
| 3D 교육과정 그래프 / 교육과정 성운 | 교육과정 전체를 둘러보고 예상하지 못한 교과 연결을 발견합니다. | 성취기준 담기 후 새 프로젝트 시작. 선택한 기준을 이웃 탐색으로 넘기는 경로도 있음. |
| 교과 연결 탐색의 이웃 | 관심 있는 성취기준과 연결되는 다른 성취기준을 찾습니다. | 선택한 기준을 담고 새 프로젝트 생성 화면으로 이동. |
| 교과 연결 탐색의 주제 | 관심 주제로 여러 교과의 성취기준을 찾습니다. | 같은 담기와 새 프로젝트 생성 경로. |
| 교과 연결 탐색의 과목쌍 | 함께 수업할 두 과목 사이의 연결을 찾습니다. | 같은 담기 경로. AI로 추가 연결을 제안받는 기능도 있음. |
| 교과 연결 탐색의 계열 | 학년을 넘나드는 연결을 살펴봅니다. | 같은 담기 경로. 표시된 연결을 공식적인 선수 학습 순서로 단정하지 않도록 안내 필요. |
| 실생활 문제 시나리오 | 선택한 연결로 어떤 생활 속 문제를 다룰 수 있는지 예시를 봅니다. | 성취기준과 제목·설명 등을 새 프로젝트 생성의 초기값으로 전달. |
| 미래보기 실험실 / 연결 아이디어 탐색 | 선택한 성취기준의 연결을 보고 여덟 관점의 수업 아이디어를 비교합니다. | 독립 진입 시 새 프로젝트 초기값 전달. 기존 프로젝트 A-3에서 진입하면 검토용 초안을 복사해 원래 프로젝트에서 검토·저장. |
| 프로젝트 안 성취기준 탐색 | 진행 중인 프로젝트에 필요한 성취기준을 찾고 추가합니다. | 키워드 검색, 의미 검색, AI 융합 추천, 융합 궁합을 제공하며 선택 결과를 해당 프로젝트에 추가. |
| 새 프로젝트 생성의 성취기준 추천 | 학년과 과목에 맞는 출발 재료를 고릅니다. | 프로젝트 생성 과정 안에서 선택. 별도 탐색 서비스로 분리할 필요가 적음. |

이웃·주제·계열·과목쌍은 한 탐색 도구의 네 가지 보기다. 각각을 독립된 상위 메뉴로 늘리는 것은 권하지 않는다. 실생활 문제 시나리오는 특정 연결의 구체적인 예시, 미래보기는 성취기준 조합의 여러 수업 가능성 비교라는 차이를 안내하면 함께 유지할 수 있다.

시뮬레이션은 별도의 역할을 갖는다. 홈의 **데모 체험**은 AI가 만드는 설계 예시를 체험하는 경로이고, 프로젝트의 **여기부터 시뮬레이션**은 현재 설계를 바탕으로 남은 설계와 보고서를 별도 참고본에서 살펴보는 경로다. 실제 학생의 학습 결과를 예측하는 기능으로 소개하면 안 된다. 임용 실연 준비 역시 대상과 목적이 달라 교과 탐색 메뉴와 묶지 않는 편이 좋다.

**현재 구조에서 발견한 문제**

1. 홈에는 3D 그래프가 직접 노출되지만, 실용적인 네 가지 탐색 보기는 3D의 설계 모드 전환이나 사용 안내를 거쳐 발견하게 된다. 교사가 당장 재료를 찾는 목적과 진입 비중이 맞지 않는다.
2. 같은 기능이 위치마다 다른 이름으로 보인다. 미래보기 실험실과 연결 아이디어 탐색, 3D 교육과정 그래프와 교육과정 성운, 교과 연결 탐색과 설계 모드의 관계를 사용자가 기억해야 한다. 특히 설계 모드는 프로젝트의 단계별 설계와 혼동할 여지가 있다.
3. 결과의 상태가 다르다. 독립 탐색의 담기는 브라우저 세션의 후보 목록이고, 프로젝트 안 성취기준 추가는 프로젝트 데이터 변경이며, A-3 초안 복사는 아직 보드 저장이 아니다. 버튼에 이 차이를 일관되게 드러낼 필요가 있다.
4. 독립 탐색의 주요 완료 동작이 새 프로젝트 시작에 맞춰져 있다. 기존 프로젝트가 있는 사용자를 위한 복귀 경로는 A-3 미래보기에서 마련되어 있지만, 탐색 도구 전체에 공통으로 적용되지는 않는다.
5. 새 프로젝트로 넘어갈 때 성취기준과 제목·설명 등은 전달되지만, 선택한 아이디어 전체와 채택 이유가 모두 설계 이력으로 저장되는 것은 아니다. 후보 탐색과 설계 확정 사이를 명확히 안내해야 한다.

**제안하는 메뉴와 버튼 배치**

상위 구조는 **내 워크스페이스 · 수업 탐색 · 사용 안내**로 정리하는 안을 권한다. 수업 탐색 안에는 성취기준을 찾는 경로와 미래보기로 아이디어를 비교하는 경로를 주요 선택지로 두고, 3D 전체 지도는 바로 접근 가능한 보조 보기로 배치한다. 3D의 시각적 매력은 연수 도입과 자유 탐색에서 계속 활용하되 모든 사용자가 반드시 거쳐야 하는 화면으로 만들지는 않는다.

| 현재 표현 | 제안하는 표현과 위치 |
| --- | --- |
| 설계 모드 | 성취기준 연결 찾기. 수업 탐색의 주요 진입점. |
| 이웃 / 주제 / 과목쌍 / 계열 | 성취기준에서 찾기 / 주제로 찾기 / 두 과목으로 찾기 / 학년 간 연결 보기. 한 화면 안의 보기 전환. |
| 미래보기 실험실 | 미래보기. 설명은 선택한 성취기준으로 수업 아이디어 비교하기. |
| A-3 연결 아이디어 탐색 | 미래보기로 연결 아이디어 검토. 기존 프로젝트 문맥과 공통 기능명을 함께 표시. |
| 실생활 문제 시나리오 | 이 연결로 수업 예시 보기. 연결 상세 안에 배치. |
| 3D 교육과정 그래프 | 교육과정 전체 지도. 3D임을 보조 설명으로 표시. |
| 데모 체험 | AI 설계 예시 체험. 사용 안내와 처음 시작하는 사용자를 위한 영역에 배치. |
| 여기부터 시뮬레이션 | 현재 설계로 시뮬레이션. 원본을 유지하고 별도 참고본을 만든다는 설명 동반. |

위 이름과 위치는 아직 적용하지 않은 제안이다. 계열처럼 전문적인 기능은 필요할 때 펼칠 수 있게 하되, 자주 사용하는 기능을 여러 단계 안쪽으로 숨기지 않아야 한다. 이는 핵심 선택지를 먼저 제시하고 전문 옵션을 뒤에 두는 [점진적 공개 원칙](https://www.nngroup.com/articles/progressive-disclosure/)을 이 서비스에 적용한 제안이다. 교과·주제·아이디어는 서로 오가며 조정하므로 탐색 전체를 강제적인 일방향 마법사로 바꾸지는 않는다.

**프로젝트와 연결하는 공통 안내**

탐색 화면 상단에는 새 수업 준비 중인지, 특정 프로젝트의 어느 단계에서 왔는지를 보여주는 문맥 표시를 둔다. 후보 목록에는 담은 성취기준이라고 표시하고, 아직 프로젝트에 저장되지 않았으면 그 상태를 함께 안내한다.

새 수업 준비에서는 **이 조합으로 새 프로젝트 만들기**, 기존 프로젝트에서는 **현재 프로젝트에서 검토하기**가 주된 다음 행동이 되도록 제안한다. 후자는 모든 탐색 도구에 구현된 기능이 아니므로 별도 개발 범위다. 기존 프로젝트 선택·권한·성취기준 중복·단계 상태를 확인해야 하며, 기존 내용을 자동 덮어쓰거나 단계를 자동 완료하는 동작으로 만들지 않는다.

A-3 미래보기는 현재 수동 전달 흐름을 유지하면서 다음 안내를 명확히 한다.

**A-3에서 미래보기 열기 → 연결과 아이디어 비교 → 초안 복사 → 원래 프로젝트의 A-3 대화에서 검토 → 보드에 저장 → 다음 단계**

복사 버튼 옆에는 복사는 저장이 아닙니다를 안내한다. 저장 여부를 실제 데이터로 확인하지 않은 채 반영 완료라고 표시하지 않는다. 시뮬레이션에는 보드에 저장된 설계가 사용된다는 점을 함께 설명한다. 생략한 단계가 있는 프로젝트는 현재 이어서 시뮬레이션을 지원하지 않으므로, 이 상태에서도 실행할 수 있는 것처럼 안내하면 안 된다.

**연수에서 사용할 안내 흐름**

- 주제는 있지만 교과 연결이 막막한 교사: 주제로 찾기에서 재료를 고르고, 필요하면 미래보기에서 아이디어를 비교한 뒤 새 프로젝트를 시작하도록 안내한다. 모든 화면을 반드시 거칠 필요는 없다.
- 함께할 과목이 정해진 교사: 두 과목의 연결을 찾고, 연결별 수업 예시 또는 미래보기를 통해 방향을 구체화하도록 안내한다.
- 이미 프로젝트가 있는 교사: 해당 프로젝트에서 성취기준을 찾고 A-3 미래보기로 검토한 뒤, 원래 프로젝트에 돌아와 저장하도록 안내한다. 홈에서 다시 새 프로젝트를 만들도록 유도하지 않는다.

연수 도입에서는 3D 지도로 서비스의 연결 관점을 짧게 보여준 뒤, 준비된 샘플 하나로 아이디어 검토부터 프로젝트 반영까지 한 번 완주하는 구성을 권한다. 다른 탐색 방식은 상황별 선택지로 소개한다.

**연수 전 탐색 개선과 검증 체크리스트**

- [ ] 교사 사용성 점검에서 막힌 버튼·복귀 지점·용어를 모아 위 사용성 가설과 비교한다.
- [ ] 먼저 이름과 설명을 통일하고, 담기·복사·보드 저장의 상태 차이를 명확히 한다.
- [ ] 성취기준 연결 찾기와 미래보기의 주요 진입점을 정리하고, 3D 지도와 AI 설계 예시 체험의 위치를 조정한다.
- [ ] 기존 프로젝트 문맥과 복귀 버튼을 통일한다. 공통 프로젝트 전달 기능은 별도 변경으로 나눈다.
- [ ] 교사 사용성 테스트에서 도움 없이 탐색 시작, 후보 선택, A-3 복귀와 저장을 수행할 수 있는지 확인한다. 오작동뿐 아니라 불필요한 새 프로젝트 생성과 길 잃음도 기록한다.
- [ ] 새 프로젝트, 기존 프로젝트 A-3, 단계 건너뛰기, 읽기 전용·시뮬레이션 프로젝트, 빈 선택·실패·재시도·새로고침, 모바일을 회귀 검증한다. 시뮬레이션과 보고서까지 이어지는 경로를 확인한다.
- [ ] 전체 테스트와 빌드, 실제 서비스 확인 결과를 구분해 기록한 뒤 배포한다. 변경을 작은 PR로 나누고 각 변경의 롤백 대상을 정한다.
- [ ] 연수 전에는 실제 구버전 코드 삭제를 실행하지 않는다. 기존 URL·API·공유 의존성을 보존한다.
