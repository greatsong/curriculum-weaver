# 수업 아이디어 탐색 설계안

2026년 10월 3일 · 설계 기록 및 최종 반영 범위

최종 사용자 지시: **이미지 빼고 반영**. 이번 제품 변경은 이미지·섬네일 없는 세 진입점, 상황별 짧은 안내, 기존 프로젝트 A-3 안내, 탐색 대상과 저장 상태 구분이다. 실제 서비스 로고와 기능 내부의 3D 지도·키워드 연결 그래프는 유지한다. 아래 시각 시안과 선택 전달·다과목 팀 선택 등의 확장 명세는 설계 기록이며 전부 이번에 구현됐다는 뜻이 아니다. 가상의 예시 데이터·회전 지도·원형 미래보기 시안 코드는 제품으로 옮기지 않는다.

사용자와 정리한 출발점은 자유 탐색, 과목이 정해진 팀, 성취기준이 정해진 팀, 진행 중인 프로젝트다. 서비스의 상위 제목은 **수업 아이디어 탐색**을 제안한다. 교사가 얻으려는 결과를 제목으로 삼고, 도구 이름은 각 진입 버튼에 둔다.

이 문서는 앞선 탐색 기능 검토의 ‘주요 입구 두 개와 보조 3D’ 안을 대체한다. **새 수업의 세 입구와 기존 프로젝트의 한 경로**로 정리한다. 구버전 코드 삭제는 연수 이후에 검토한다. 이번 반영 범위를 넘어선 추가 기능은 별도 변경으로 검증한다.

**첫 화면**

제목: 수업 아이디어 탐색

설명: 교과의 연결을 발견하고, 우리 팀만의 수업으로 엮어보세요.

시각 구성: 개별 섬네일을 넣은 세 카드 방식은 사용자 피드백에 따라 철회한다. 실제 커리큘럼 위버 로고를 헤더에 사용하고, 로고의 다색 점과 빛의 연결을 넓은 탐색 영역으로 확장한다. 밝은 서비스 기본 화면·파란 조작 버튼은 기존 디자인을 따른다. 어두운 탐색 영역 안에서 소개와 세 진입점을 하나로 묶고, 진행 중인 프로젝트는 아래에서 명확히 구분한다. 모바일은 소개 → 연결 표현 → 세 진입점을 세로로 배치한다.

시안은 홈에서 끝나지 않고 3D 자유 탐색, 과목 중심 탐색, 미래보기, 새 프로젝트 준비, 기존 프로젝트의 A-3 검토까지 이동할 수 있다. 3D는 예시 점군을 원근 투영하며 드래그 회전과 과목 선택을 제공한다. 실제 교육과정 데이터나 AI 호출을 연결한 구현은 아니다. 미래보기는 기존 민트색 빛의 원과 여덟 관점의 상세 화면을 이어받는다. 기존 키워드 연결 그래프는 제품 구현에서 유지하며, 시안의 간략한 선택 과목 표시는 이를 대체하는 명세가 아니다.

| 사용자 상태 | 입구 | 진입 후 첫 행동 | 다음 행동 |
| --- | --- | --- | --- |
| 아직 방향이 정해지지 않음 | 3D 자유 탐색 | 관심 교과·성취기준과 연결 근거 살펴보기 | 기준 담기 → 미래보기 또는 과목 중심 상세 탐색 |
| 함께할 과목이 정해짐 | 과목 중심 탐색 | 학년과 팀 과목 확인 → 과목 간 연결 비교 | 기준 담기 → 미래보기 |
| 사용할 성취기준을 알고 있음 | 미래보기 | 코드 입력·검색·담아온 기준 확인 | 연결 검토 → 여덟 관점의 아이디어 비교 |
| 프로젝트 진행 중 | 해당 프로젝트의 A-3 미래보기 | 프로젝트 등록 기준·A-3 기준 확인 | 탐색 초안을 원래 A-3로 가져와 검토 |

홈에서 새 수업의 세 입구를 같은 수준으로 배치한다. 기존 프로젝트 경로는 별도 영역에 프로젝트 제목·현재 단계와 함께 둔다. 해당 프로젝트가 A-3가 아니라면 현재 단계를 먼저 열고, 탐색 때문에 진행 단계를 자동으로 옮기지 않는다. 프로젝트가 여러 개면 사용자가 고른 대상의 제목과 단계를 확인한 뒤 진입한다. 홈에 프로젝트 목록이 아직 로드되지 않았거나 조회에 실패하면 ‘프로젝트 없음’으로 단정하지 않는다.

주제가 있는 교사의 기존 주제 검색은 하위 보조 경로로 유지한다. 최초 화면에 네 번째 주요 카드까지 늘리지 않는다. AI 설계 예시 체험은 사용 안내에 배치하며, 미래보기의 수업 아이디어 비교와 역할을 구분한다.

**3D 자유 탐색**

3D는 전체 교육과정에서 예상하지 못한 관계를 발견하는 도구다. 사용자는 움직임을 멈춰 읽을 수 있어야 하며, 교과·성취기준을 선택하면 원문과 연결 근거를 함께 확인한다. 흥미로운 선만 보게 하지 않고 선택할 성취기준을 명확히 드러낸다.

선택한 기준은 하단의 공통 후보 목록에 쌓인다. 두 개 이상이면 ‘이 기준으로 미래보기’를 제공한다. ‘과목 중심으로 자세히 살펴보기’는 선택과 현재 프로젝트 문맥을 유지한다. 3D 표시가 어려운 기기에서도 같은 기준·근거를 목록으로 선택할 수 있어야 한다. 모바일에서도 자료와 다음 행동에 접근할 수 있게 한다.

현재 구현에는 담기·새 프로젝트 시작·이웃 탐색 전환이 있다. 미래보기로 선택과 프로젝트 문맥을 전달하는 공통 경로는 **추가 구현 항목**이다. 시안의 지도는 이 선택 동작과 화면 배치를 보여주는 예시이며 완성된 3D 렌더러가 아니다.

**과목 중심 탐색**

팀 과목은 탐색 중 유지한다. 3과목 이상을 선택한 경우, 기존 두 과목 연결 기능을 활용하여 조합별로 살펴본다. 예를 들어 미술·정보·영어 팀은 미술↔정보, 정보↔영어, 미술↔영어를 전환하고 고른 기준을 하나의 후보 목록에 모은다.

과목 조합 전환은 후보 목록을 초기화하지 않는다. 팀 과목을 제거할 때도 이미 고른 기준을 조용히 삭제하지 않는다. 해당 기준을 ‘현재 팀 과목 밖의 후보’로 표시하고 사용자가 유지·제거하도록 한다. 학년 변경으로 범위가 달라져도 동일하다.

한 화면에서 여러 과목을 동시에 묶는 새 AI 연결 알고리즘까지 도입하지 않는다. 팀의 다과목 문맥은 유지하되 비교는 기존 두 과목 단위로 한다. 연결 없음·로딩·조회 실패를 구분하고, 연결되지 않은 과목을 억지로 이어 붙이지 않는다. 미래보기로 넘길 기준은 기존 한도인 2~7개이며 최대 개수를 목표로 채우도록 유도하지 않는다.

**미래보기**

기준을 알고 온 팀은 3D나 과목 탐색을 거치지 않고 바로 시작한다. 다른 탐색에서 넘어온 기준은 자동으로 표시하되 원문과 과목을 확인할 수 있어야 한다. 7개를 초과한 선택은 임의로 자르지 않고 이번에 사용할 기준을 고르게 한다.

화면 순서는 선택한 기준 → 키워드 연결과 근거 → 여덟 관점의 아이디어 비교 → 사용할 아이디어 선택이다. 기존의 과목별 빛의 원, 키워드 연결, 미래 전환과 상세 화면을 유지하는 방향이다. 샘플은 기준을 아직 고르지 않은 새 수업에 우선 보여주고, 기존 프로젝트에서 가져온 기준을 샘플로 조용히 교체하지 않는다.

새 수업의 완료 행동은 ‘이 아이디어로 프로젝트 준비’다. 워크스페이스와 생성 정보를 확인하는 단계로 이어지며, 생성 성공 전에는 프로젝트에 저장됐다고 표시하지 않는다. 기존 제목·설명·성취기준 초기값 전달 범위와 아이디어 전체 보존 범위는 구현 시 구분한다. 전체 활동·근거가 저장되지 않는다면 모두 저장되는 것처럼 안내하지 않는다.

기존 프로젝트의 완료 행동은 ‘이 아이디어를 A-3에서 검토’다. 같은 화면이어도 새 프로젝트 생성 버튼을 주 행동으로 제시하지 않는다.

**진행 중인 프로젝트의 A-3 경로**

프로젝트 A-3 → 미래보기 → 연결과 아이디어 비교 → 전달할 초안 준비 → 복사 → 원래 A-3 대화에 붙여넣기 → 기존 비전·주제·분석과 비교 → AI가 제안한 조정안 검토 → 제안 수락 → 저장 성공 확인 → 사용자가 다음 단계로 이동.

Claude의 PR #147에서 제안 수락은 보드 저장과 후속 AI 안내로 이어진다. 따라서 수락한 뒤 별도 저장 버튼을 다시 누르도록 요구하지 않는다. 직접 편집한 경우에는 기존 편집기의 저장 동작을 따른다. 복사만으로 보드가 바뀌지는 않으며 수락 또는 저장 실패를 성공으로 표시하지 않는다.

미래보기 자체가 기존 비전·주제를 모두 생성 입력으로 사용하는 것은 아니다. 성취기준에서 확장한 탐색 결과를 A-3에서 기존 설계에 맞춰 검토하는 구조로 안내한다. 이 설명은 Claude의 비전 기반 성취기준 추천과 미래보기의 역할 차이를 드러낸다.

시뮬레이션은 저장된 프로젝트 설계를 사용하는 별도 참고본이다. 복사한 탐색 초안만으로 시뮬레이션에 반영됐다고 안내하지 않는다. 생략된 단계가 있는 프로젝트의 이어서 시뮬레이션 제한도 그대로 표시한다.

**공통 문맥과 선택 보존**

- 모든 탐색 화면은 ‘새 수업 준비’ 또는 ‘프로젝트 제목 · 출발 단계’를 표시한다.
- 새 수업 후보와 기존 프로젝트 후보를 서로 분리한다. 프로젝트 간에도 후보가 섞이지 않게 한다.
- 3D·과목 탐색·미래보기 간 이동에는 선택한 기준을 유지한다. 새 탭·새로고침·뒤로가기에도 URL과 탐색 상태가 일관돼야 한다.
- 브라우저 임시 후보를 영구 저장으로 표현하지 않는다. 복원할 수 없는 선택은 조용히 빈 값으로 바꾸지 말고 안내한다.
- 홈에서 기존 프로젝트를 추측해 연결하지 않는다. 명시적으로 선택한 프로젝트만 대상으로 한다.
- 돌아가기에는 원래 프로젝트와 단계를 보존한다. 탐색이 진행 단계·건너뛰기·권한을 바꾸지 않는다.

**검토 상태와 저장 상태**

| 확인된 사실 | 표시할 상태 | 피해야 할 표현 |
| --- | --- | --- |
| 탐색에서 기준이나 아이디어를 고름 | 검토 중 · 프로젝트 미반영 | 저장 완료 |
| 전달할 텍스트를 준비함 | 전달할 초안 준비됨 | 프로젝트에 적용됨 |
| 복사 요청이 성공함 | 복사 완료 · A-3에서 검토 필요 | 보드 반영 완료 |
| 기존 보드를 서버에서 읽음 | 마지막 조회 시점의 보드 저장 상태 | 이번 탐색 아이디어 채택 완료 |
| 제안 수락의 저장 요청이 성공함 | 제안이 보드에 반영됨 | 저장 응답 전 성공 표시 |
| 저장 결과를 확인하지 못함 | 저장 결과 확인 필요 · 다시 확인 | 실패가 확실하지 않은데 미저장 단정 |

이전부터 저장돼 있던 보드와 이번에 고른 아이디어의 채택 여부는 별개다. 현재 수동 복사 방식에서는 미래보기 화면이 채택 여부를 자동 판정하지 않는다. 실제 반영 성공은 원래 프로젝트의 저장 응답에 근거해 알린다.

**연수 전 구현을 나눌 단위**

1. 제목·세 진입점·A-3 안내·일관된 상태 표현. 서버 추천·제안 수락 로직은 유지한다.
2. 탐색 간 선택 전달과 복귀 문맥. 새 수업/프로젝트별 후보 분리와 초과 선택 안내를 함께 검증한다.
3. 팀의 여러 과목 선택과 기존 두 과목 보기 연결. 새 다과목 AI 생성 기능으로 범위를 넓히지 않는다.

각 단위는 승인된 범위를 확인하고 별도 검증 후 병합한다. 구버전 화면·API·공유 코드 삭제는 포함하지 않는다. 삭제 검토 알림은 10월 11일 오전 9시 한국 시간으로 등록돼 있다.

**승인 후 검증할 주요 상황**

- 세 입구 각각에서 기준 선택 → 미래보기 → 새 프로젝트 생성까지 전달 누락 여부.
- A-3 진입 → 원래 프로젝트 복귀 → 제안 수락의 성공·실패 → 다음 단계와 시뮬레이션·보고서.
- 두 과목에서 세 과목 이상으로 변경, 조합 왕복, 과목 제거, 학년 변경, 0·1·2·7·8개 후보.
